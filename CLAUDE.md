# SecondBrain

SecondBrain is my personal knowledge base and coding memory.

## Purpose

Use this vault to store:

- Personal coding standards.
- Development practices.
- Important technical decisions.
- Project knowledge worth remembering.
- Claude Code session summaries.

This is not intended to be a general programming encyclopedia.

Prefer actionable knowledge and personal standards over tutorials.

## Coding Standards

The `Coding Standards/` directory contains my preferred programming standards.

When writing, reviewing, refactoring, or designing code:

1. Apply `Coding Standards/General.md`.
2. Identify the technologies used by the current project.
3. Apply the relevant technology-specific standards.
4. Treat these standards as my preferred defaults.

Relevant files include:

- Kotlin.md
- Android.md
- Compose.md
- React.md
- TypeScript.md
- Java.md
- PostgreSQL.md

Do not modify Coding Standards unless I explicitly ask you to.

If project-specific requirements conflict with a personal standard, follow the project requirement.

## SecondBrain notes

Before creating a new permanent knowledge note:

- Search for an existing relevant note.
- Prefer updating or linking existing knowledge over creating duplicates.
- Do not create permanent notes automatically unless explicitly requested.

## Session summaries

When I explicitly request a session summary:

- Summarize the useful information from the current session.
- Save it under `Sessions/`.
- Do not copy the conversation verbatim.
- Capture decisions, solutions, lessons, best practices, and remaining work.
- Do not automatically modify Coding Standards.

## Best-practice proposals

If a session reveals a potentially useful permanent coding practice:

- Mention it as a proposed improvement.
- Do not automatically add it to Coding Standards.
- Only modify Coding Standards after I explicitly approve the change.
